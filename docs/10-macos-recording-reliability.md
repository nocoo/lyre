# macOS 权限、输入设备与会议提醒优化

2026-09-15。基于 v1.8.1 和本轮单窗口 UI 改版，保留双音轨录音、播放、手动上传和默认关闭的自动上传。本轮优化对应 v2.0.0，验证过程没有替换本机已安装应用。

## 调查结果

| 痛点 | 发现的原因 | 当前处理 |
| --- | --- | --- |
| 已授权仍被要求设置权限 | UI 在刷新前读取初始或缓存状态；ScreenCaptureKit 内容查询的任意异常被当成拒绝授权 | 启动、返回应用和录制入口重新读取系统授权；检查与申请分离 |
| 更新后麦克风授权失效 | 本机已安装版本使用 ad-hoc 签名，designated requirement 依赖构建哈希，没有 TeamIdentifier | 正式打包要求 Developer ID Application；本地 ad-hoc 必须显式选择 |
| 自动输入不稳定 | AVFoundation 默认设备解析与系统当前输入可能不同步；设备消失时永久清除已保存的选择 | 用 CoreAudio 默认输入 UID；保留偏好，单独解析实际可用设备 |
| Teams 误提醒与干扰 | 两个窗口就算会议；单独占用麦克风即可触发；开始/结束使用相同的短去抖；停止建议未区分手动录音 | 移除窗口数量规则，加强音频证据，开始确认 10 秒、结束确认 30 秒，按录音会话匹配停止建议 |
| 弹窗风格和焦点问题 | NSAlert 激活应用并运行模态循环；删除确认使用另一套系统警告布局 | 共享 SwiftUI 对话框；会议提醒使用不激活应用的 NSPanel，删除与前台错误使用 sheet |

## 权限

以下记录的是 **v2.0.0 的实现**。后续发现 CG 预检在进程内可能保持旧值，已增加 ScreenCaptureKit 的显式核验与重新打开恢复入口，详见[系统音频权限修复](11-macos-system-audio-permissions.md)。

v2.0.0 的 `PermissionManager.checkAll()` 只读取 `CGPreflightScreenCaptureAccess` 和 `AVCaptureDevice.authorizationStatus`。后台检测和访问页面不会申请权限，也不会因为窗口查询失败把授权改成 denied。检查与显式申请在 MainActor 上执行；麦克风申请会合并重复点击，已允许或已拒绝时不会重新发起申请。

`LyreApp.toggleRecording()` 先刷新再决定是否导航到权限页；共享录音管理器仍在开始前刷新状态。停止录音不受新的权限状态阻挡。权限页继续在用户返回系统设置后更新，并提供 Allow access / Open Settings / Allowed 的明确状态。

**跨更新授权仍有签名依赖。** 调查时本机没有可用代码签名证书。应用逻辑无法让每次变化的 ad-hoc 签名获得稳定 TCC 身份，也没有重置或修改用户现有权限。切换到稳定 Developer ID 签名时可能仍需重新授权一次，之后的更新应保持同一 bundle ID 与有效签名身份。

v2.0.0 的 DMG 沿用此前版本的 ad-hoc 签名，通过显式构建选项生成，未经过 Apple 公证。更新后仍可能需要重新授予系统音频或麦克风权限；此发行包不具备 Developer ID 签名带来的跨更新身份稳定性。

正式打包示例：

```bash
LYRE_CODE_SIGN_IDENTITY='Developer ID Application: Your Name (TEAMID)' \
LYRE_DEVELOPMENT_TEAM=TEAMID bun run macos:dmg
```

仅供本地临时使用的打包：

```bash
LYRE_ALLOW_ADHOC=1 bun run macos:dmg
```

脚本在清理 `build/` 之前检查签名配置，签名校验失败会终止。公证仍需在分发前另行完成。

## 输入设备

- **Automatic · Follow macOS**：使用 macOS Sound 中的当前默认输入，录制过程中默认设备改变时也更新。
- **指定设备**：该选择跨启动保留。暂时断连时使用系统默认输入，设备重连后恢复；界面说明当前替代来源。
- **录音中的选择**：开始时保存本次录音的输入策略。修改选择器影响下一次录音；当前录音仍按原策略处理系统默认变化和设备重连。
- **没有输入**：开始时给出明确错误，不交给 ScreenCaptureKit 猜测设备。录音中失去全部输入时继续系统音频，并显示麦克风不可用。
- **更新失败**：保留原配置并显示提示，不把切换失败当成麦克风权限丢失。

CoreAudio 同时监听设备列表和默认输入变化，释放对象时移除监听；短时间的设备变化合并处理，ScreenCaptureKit 配置更新串行执行，停止捕获前取消并等待更新。录制工具栏与菜单栏显示当前输入；保存的偏好和实际来源分别维护。

设备启动失败时清理录音回调并收尾编码器，允许再次尝试，不触发自动上传。原始采样队列、双音轨编码和上传前混音保持原有路径。

## Teams 提醒

新安装默认关闭，已有持久化值保持不变，包括旧版保存的开启值。关闭设置会暂停检测并撤回正在显示的提醒。

开始判断需要持续的双向 Teams 音频活动，或单向音频加明确的会议窗口标题。单独的麦克风预览、多个聊天窗口和空闲会议标题不再足以判断开始。已确认的会议允许静音、窗口最小化和切换 Space；窗口不在屏幕上不再等同于会议结束。

使用单调时间确认连续信号：开始 10 秒，结束 30 秒；Teams 运行时每 5 秒采样，未运行时每 30 秒检查。Teams 进程退出可直接确认结束。启动或重新启用时的首次观察只建立基线，不提醒已经进行中的会议。

查询失败和未知音频状态不会被当作结束，也会重置待确认时间。单轮查询不重叠；暂停、恢复或进程退出后，旧查询的迟到结果被丢弃。

每次会议最多提供一次开始与结束建议。开始提醒接受后记录该次录音的 UUID，只有同一录音仍在进行时才提供结束建议；中途手动停止、重新录制后不会误停新录音。确认前再次检查设置、会议状态、操作繁忙状态与会话身份。提醒期间仍消费新事件，过期提示会撤回。

提醒不激活应用、不使用模态循环，20 秒后自动消失，支持关闭、取消或明确接受。录音始终由用户决定。检测仍基于本机音频和窗口信号，不能保证识别每一种 Teams 版本、测试通话或自定义会议标题。

## 对话框

`LyreDialogView` 统一 440 pt 宽度、24 pt 内边距、32 pt 按钮高度与 144 pt 主操作按钮，沿用暖棕 / 浅杏色和深浅主题。删除确认显示文件名和后果，Return 默认取消，Escape 可关闭；文件上传保护在确认时与执行时均保留。

前台录音错误附着到主窗口；主窗口不活跃时使用不抢焦点的提示面板。重复的相同错误合并显示。系统授权弹窗与文件夹选择器继续由 macOS 提供。

## 验证

- 普通原生测试通过：**243 个测试定义，参数展开后 263 次通过，0 次失败，3 个真实录音测试跳过**。结果：`test-results/macos/run-E2ytrI/Tests.xcresult`。
- Release 构建、SwiftLint strict、`git diff --check` 通过；Release 验证关闭代码签名。
- 新增或更新回归覆盖：旧权限刷新、拒绝后外部授权、重复申请、自动输入变化、设备断连/重连、开始失败清理、Teams 证据与确认时间、异步查询暂停、过期提醒、手动录音与并发录制入口。
- 本机只读设备检查：7 个 CoreAudio 输入 UID 均与 AVFoundation 匹配，系统默认 UID 也匹配；未启动麦克风捕获。
- 缺少身份或指定不存在的证书时，打包脚本在修改构建目录前退出；shell 语法检查通过。
- 隔离宿主渲染 **33 个场景、66 张截图**。会议提醒截图来自实际非激活面板，并检查面板未取得键盘焦点；错误截图来自附着到主窗口的实际 sheet，验证显示与关闭；删除截图展示实际共享组件。画廊检查覆盖全部图片、主题切换、场景定位、键盘导航及桌面/窄视口。

未启动日常 Lyre、加入真实 Teams 会议、录制真实音频、重置 TCC、替换已安装应用或上传线上数据。蓝牙/USB 录音中热插拔的实际音频连续性、不同 Teams 版本的召回率，以及正式签名版本跨更新的授权保留，仍需对应设备与签名环境验证。
